# 蚂蚁百宝箱 · 创建助手提示词（评分输出规范 + 逐题反馈）

> 用途：粘贴给**百宝箱应用内的「创建助手」**，用于**更新训练接口 `evaluate`（评分）阶段的输出规范**：
> ① 修正 `suggestions` 放错层级 / JSON 尾随多余字符的问题；② 新增**逐题反馈**（每道题一条点评 + 建议）。
> ⚠️ 只改系统提示词与评分输出，**不改接口路径/出入参**，不动对话、报告、能力补充测评链路。

## 一、提示词全文（直接整段复制粘贴给创建助手）

```
请更新当前应用里三个「职场训练接口」的**评分输出规范**（仅 evaluate 阶段），只改系统提示词与输出结构，
不要改接口路径与出入参。

【现在的问题（来自真实返回，务必针对性修正）】
1. `suggestions` 被写到了与 `training_evaluation` **平级的顶层**：
   {"training_evaluation":{…dimensions,evidence,total,comment…},"suggestions":["…","…"]}
   → 后端只认评分对象**内部**的 suggestions，导致整份评分被判「缺少改进建议」、分数不展示。
2. JSON 末尾多了一个 `}`（尾随多余内容），也会让严格解析失败。
3. 只有整体评语，**没有逐题反馈**：用户看不到"第 1 题答得怎么样、第 3 题错在哪、每道题该怎么改"。

【硬要求（逐条遵守）】

■ 1. 只在 evaluate 阶段输出**一个** JSON 对象，结构固定：
{
  "training_evaluation": {
    "scenario": "<本场景>",
    "templateVersion": "<本模板版本>",
    "rubricVersion": "<本规则版本>",
    "dimensions": { "<维度键>": 0 },
    "evidence": [ { "dimension": "<维度键>", "evidenceId": "A2E1" } ],
    "total": 0,
    "comment": "总体评价（≥80 字）",
    "suggestions": [ "整体改进建议（2~4 条，每条 ≤100 字）" ],
    "perQuestion": [
      { "questionNo": 1, "dimension": "<维度键>", "verdict": "correct|partial|wrong",
        "comment": "该题点评（≤120 字）", "suggestion": "该题改进建议（≤120 字）" }
    ]
  }
}

■ 2. `comment` 是**总体评价**：写清整体水平、能胜任什么、最明显的缺口是什么（不要只复述题目）。
■ 3. `suggestions` 是**整体改进建议**：2~4 条，每条可执行、可检验。
■ 4. `perQuestion` 必须**每道题一条**（含追问轮也算）：
   - `questionNo` 用题目序号（1..N）；`dimension` 用该题所属维度键；
   - `verdict`：**技术题按事实判定**——答对=correct、部分对=partial、答错=wrong；
     经历/情境题按信息完整度判 partial 或 correct；
   - `comment` 一句话说清"答得怎么样（对/错/缺什么）"；`suggestion` 一条"下次怎么答"。
   - **不要**只给前几题，也不要合并成一整段。
■ 5. `suggestions`、`comment`、`perQuestion` 必须放在 `training_evaluation` **内部**，
   **不要**放到与它平级的顶层。
■ 6. 整个回复**只能有一个 JSON 对象**：不要输出第二个对象、不要在末尾多写 `}`、不要加任何说明文字或围栏。
■ 7. 评语与建议中**不要使用英文双引号**（如需强调请用「」）——裸引号会破坏 JSON。
■ 8. `total` 可写可不写（后代会按权重重算，不采纳你的值）。
■ 9. 逐题 verdict 与维度分要一致：技术题判 wrong 的，该维度分不应偏高。

【一份完整示例（结构照抄，内容按实际作答替换）】
说明：以下为示例，仅演示结构；实际输出时 dimensions 必须与本场景维度集合完全一致（4 个键），
evidence 必须引用任务指令给出的「冻结证据目录」里的编号。
（见请参考下方"示例"小节）

【交付要求】
① 给出更新后的三个训练接口系统提示词全文（重点是 evaluate 评分输出的部分）
② 附一份完整的评分示例（含 perQuestion 逐题反馈 4~6 条）
③ 说明如何保证与其它接口（能力补充测评、主对话、报告）互不影响
④ 改完是否需要重新发布才生效
```

## 三、本仓库（星职 Java 后端）已同步的容错（即使模型偶发不规范也不丢分）

| 位置 | 容错 |
|---|---|
| `TrainingScoreValidator` | ① 模型把 `suggestions`/`comment`/`perQuestion` 放到**顶层**时自动**归位**到评分对象内；② `comment` 缺失 → 按维度自动生成兜底评语；③ `suggestions` 缺失 → 按最弱维度自动生成兜底建议；④ `perQuestion` 逐题校验（题号/维度/verdict/点评/建议）并下发前端 |
| `TrainingService.readEvaluation` | 严格解析失败 → 裸引号修复 / 宽松解析（**允许尾随多余字符**）→ 仍失败才打印原文 |
| 前端 `TrainingView` | 新增**逐题反馈**区块：题号 + 维度 + `答对/部分正确/答错` + 点评 + 单题建议 |

> 即便如此，**逐题反馈的内容质量仍取决于平台**：`perQuestion` 只能由模型生成，
> 所以请务必按上面第一节更新平台提示词并**重新发布**。
