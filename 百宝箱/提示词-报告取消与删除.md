# 百宝箱提示词 · 报告任务「取消」与「删除」接口

> 用途：把本文件交给**蚂蚁百宝箱企业版**的「AI 创建 / 接口开发」助手，或提交给平台侧工程师，
> 在现有报告异步任务（`POST /api/report` + `GET /api/report/jobs/{jobId}`）基础上**再补两个接口**。
> 背景：第三方后端需要（①）生成过程中随时**停止**；（②）在个人中心**批量删除**报告并与平台同步。
> 生成时间：2026-09-19

---

## 一、取消任务（支持"随时停止"）

### 需求

```
POST /api/report/jobs/{jobId}/cancel
Content-Type: application/json
鉴权：可选 Authorization: Bearer <TBOX_API_KEY>（与其它接口一致）
```

**语义（必须严格遵守）：**

1. **立即中止**该 jobId 对应的流水线：正在跑的智能体、排队中的智能体、检索调用全部停止，不再消耗模型/检索资源。
2. **不落库**：取消的任务**不得**写入 `career_report` / `career_report_history`（即平台侧不留半成品）。
3. **幂等**：对同一 jobId 重复调用都返回成功；对**不存在的 jobId** 返回 `success=false` + 原因（不报 5xx）。
4. **已完成的任务**：`status=done` 的任务调用取消 → 视为 **no-op**（返回 `canceled:false, status:"done"`，不改动已落库的数据）。
5. 取消后，`GET /api/report/jobs/{jobId}` 应返回 `{"status":"canceled"}`（或等价的终止态），不再返回 `running`。

### 响应示例

```json
// 取消成功（进行中）
{ "canceled": true,  "status": "canceled", "jobId": "job_..." }

// 已完成，无需取消
{ "canceled": false, "status": "done",     "jobId": "job_..." }

// 任务不存在
{ "canceled": false, "status": "not_found", "message": "任务不存在或已过期" }
```

> 建议：`GET /api/report/jobs/{jobId}` 的 `status` 增加 `canceled` 取值；`progressChars/segmentChars` 保持取消前的值即可。

## 二、批量删除报告（与外部系统同步删除）

### 需求

```
POST /api/report/delete
Content-Type: application/json
鉴权：可选 Authorization: Bearer <TBOX_API_KEY>

{ "reportIds": ["6aae4b35...", "6aae4f70..."] }   // 平台报告ID（Appwrite $id）
```

**语义：**

1. **物理删除** `career_report` 中对应的行，并**级联删除** `career_report_history` 中该报告的版本快照（不留孤儿数据）。
2. **批量**：一次可传多条；逐条独立处理，**部分失败不影响其它条目**。
3. **幂等**：已不存在的 `reportId` 视为**删除成功**（不要报错）。
4. 删除后，该用户下一次生成报告时，**不得**再把已删除的报告当作"上一份报告"注入提示词。
5. 鉴权/权限：若 `reportId` 不属于调用方 `userId`，应返回 `failed`（不允许跨用户删除）。

### 响应示例

```json
{
  "deleted": ["6aae4b35...", "6aae4f70..."],
  "failed":  [ { "reportId": "6aae....", "reason": "not_found_or_forbidden" } ]
}
```

- `deleted`：成功删除（含"本就不存在"）的 id 列表
- `failed`：失败项 + 原因（`not_found_or_forbidden` / `internal_error` 等）

## 三、验收用例

| # | 用例 | 期望 |
|---|---|---|
| 1 | 任务 running 时 `POST .../cancel` | 返回 `canceled:true`；随后 `GET jobs/{jobId}` 为 `canceled`；平台库中**无**该报告 |
| 2 | 同一 jobId 连续 cancel 两次 | 两次都不报错（幂等） |
| 3 | 对 `done` 的任务 cancel | `canceled:false, status:"done"`，已落库数据不受影响 |
| 4 | 对不存在的 jobId cancel | `canceled:false, status:"not_found"`，HTTP 200 |
| 5 | 批量删除 2 条存在的报告 | `deleted` 含 2 条；`career_report` 与 `career_report_history` 均无残留 |
| 6 | 批量删除中混入 1 条不存在 | 存在的正常删；不存在的也计入 `deleted`（幂等） |
| 7 | 删除后再生成新报告 | 提示词里**不再**包含已删除的那份报告 |

## 四、本项目后端将如何对接（供平台侧参考）

- 取消：前端「停止生成」→ 后端 `POST /api/career-report/jobs/{jobId}/cancel` → 调平台取消接口；
  后端停止轮询、不写我们 MySQL。
- 删除：个人中心「管理」多选 → 后端 `POST /api/career-report/batch-delete` →
  **我们侧逻辑删除**（`is_deleted=1`）→ 用落库的 `platform_report_id` 调平台批量删除；
  平台侧失败**不阻塞**，在响应里返回 `failed` 供前端提示。
- 历史报告（改造前生成、无 `platform_report_id`）只删我们这边，平台侧跳过。
