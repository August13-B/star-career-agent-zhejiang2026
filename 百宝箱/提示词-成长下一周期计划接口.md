# 提示词 · 成长「下一周期计划」接口（A02）

> 用途：个人成长页完成任务后，用户在**最下面那个大目标**上评价本次完成难度（太简单 / 中等 / 困难），
> 点「生成下一周期计划」→ 由本接口产出**下一周期的计划与任务清单**，应用侧落库为新的一条成长计划。
>
> 请按本文件在百宝箱里**单独创建一个接口**（不要复用对话接口），并按下面「返回规范」输出。

## 一、接口定义（建议）

| 项 | 值 |
|---|---|
| 方法 | `POST` |
| 路径 | `/api/growth/next-cycle`（可自定，告知我们后配置到 `后端/.env` 的 `TBOX_GROWTH_PATH`）|
| 请求头 | `Content-Type: application/json`；如需令牌：`Authorization: Bearer <TOKEN>`（与我们现有的 `TRAINING_API_TOKEN` 同一套机制即可）|
| 超时 | 建议 ≥ 120 秒（我们这边 180 秒）|

### 请求体

```json
{
  "mode": "next_cycle",
  "difficulty": "中等",
  "plan": {
    "planName": "大三上：前端基础补齐",
    "targetJob": "前端开发工程师",
    "planType": 1,
    "startDate": "2026-03-01",
    "endDate": "2026-06-30",
    "planContent": "上一周期的总体思路……"
  },
  "tasks": [
    {
      "taskName": "完成 Vue3 组件库练习",
      "taskType": 1,
      "status": "已完成",
      "progress": 100,
      "difficultySelfRating": "中等",
      "completionDetail": "已提交任务文件：vue-components.pdf"
    },
    {
      "taskName": "投递 10 份前端实习",
      "taskType": 4,
      "status": "已完成",
      "progress": 100,
      "difficultySelfRating": "太简单",
      "completionDetail": "已提交任务文件：apply-list.xlsx"
    }
  ]
}
```

> `mode` 固定 `next_cycle`；`difficulty` ∈ `太简单 | 中等 | 困难`；
> `tasks[].taskType`：1 技能 / 2 证书 / 3 项目 / 4 实习；`status`：未开始 / 进行中 / 已完成 / 已暂停 / 已延期。

---

## 二、返回规范（**必须严格遵守**）

沿用我们现有接口的口径：**返回体本身就是一段 JSON 文本**（不要额外包一层 `code/data`），不要 Markdown 代码块、不要解释性文字。

```json
{
  "next_cycle_plan": {
    "planName": "下一周期计划名称（≤ 40 字）",
    "planContent": "总体思路，3~5 句，说明这一周期为什么这样安排",
    "startDate": "2026-07-01",
    "endDate": "2026-09-30",
    "tasks": [
      {
        "taskName": "任务名称（≤ 30 字，动词开头）",
        "taskType": 3,
        "taskDesc": "怎么做（2~3 句，具体到工具/方法/频率）",
        "expectedOutcome": "可验收的成果（例如：一个部署上线的前端项目，含 README 与演示地址）",
        "targetAbility": "对应能力维度（如 专业技能 / 项目经验 / 沟通能力）",
        "resource": ["资料或链接 1", "资料或链接 2"],
        "startDate": "2026-07-01",
        "endDate": "2026-07-21"
      }
    ]
  }
}
```

### 字段约束（务必逐条满足，否则我们无法落库）

| 字段 | 约束 |
|---|---|
| `next_cycle_plan.planName` | **非空**，≤ 40 字 |
| `next_cycle_plan.planContent` | **非空**，3~5 句 |
| `startDate` / `endDate` | `YYYY-MM-DD`；`startDate ≤ endDate`；整体周期 **4~12 周**（上一周期明显更长时可适当延长） |
| `tasks` | **3~6 条**（最多 8 条） |
| `tasks[].taskName` | **非空**，≤ 30 字，**不得与上一周期任务完全重复** |
| `tasks[].taskType` | **数字** `1/2/3/4`（不要写成 "技能" 这类文字） |
| `tasks[].expectedOutcome` | **非空**，必须可验收（避免"了解/熟悉"这类无法验收的表述） |
| `tasks[].resource` | 数组，元素为字符串（可为空数组 `[]`） |

### 内容要求

1. **只依据我们给出的上一周期材料**安排任务，不得编造学生已有的成果、经历或证书。
2. 难度自评的含义（决定这一周期的强度）：
   - `太简单` → **加量 / 提速 / 提高目标**（例如任务数取上限、周期取短、增加输出要求）；
   - `中等` → 保持节奏，在上一周期基础上**小幅加难**；
   - `困难` → **拆小步**、降低单步难度、周期适当延长、增加复盘与补基础的任务。
3. 已完成的、且已达标的能力方向不要重复安排；**优先补上一周期未完成或完成质量不足的方向**。

---

## 三、几个必须避开的坑（我们踩过）

| 坑 | 要求 |
|---|---|
| 输出里出现 ```json 围栏 | ❌ 不要加，直接输出 JSON 文本 |
| 正文里的换行被**转义**成字面量 `\n` | ❌ 不要二次转义；JSON 字符串里的换行用合法转义即可 |
| **裸英文双引号**未转义（如 `"...风险。"缺证据"集中在..."`） | ❌ 会直接破坏 JSON；请统一转义或改用「」 |
| JSON 前后带解释、结尾多一个 `}` | ❌ 只输出一个合法 JSON 对象 |
| 字段名用中文或驼峰不一致 | ❌ 严格使用上表字段名（snake_case 的 `next_cycle_plan`，其内部为驼峰）|

## 五、验收清单（发布前自检）

- [ ] 用「太简单 / 中等 / 困难」各调一次，返回的都是**合法 JSON**，无围栏、无解释、无尾随字符
- [ ] `tasks` 数量在 3~6 之间，`taskType` 是数字
- [ ] 所有日期为 `YYYY-MM-DD` 且 `startDate ≤ endDate`，整体 4~12 周
- [ ] 每条任务的 `expectedOutcome` 都能"验收"（有产物/有数量/有地址）
- [ ] 没有重复上一周期已完成且达标的任务
- [ ] 返回体内没有**裸双引号**等破坏 JSON 的字符
