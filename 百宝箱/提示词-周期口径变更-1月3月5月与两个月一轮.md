# 提示词 · 周期口径变更（1/3/5 月 + 两个月一轮）

> **本文件是「增量变更说明」，不改动原有提示词。**
> 阅读顺序：先看已有的 `提示词-报告整合与结构化目标.md`、`提示词-成长下一周期计划接口.md`，
> 再按本文件**覆盖**其中的周期口径相关表述。
> 生效范围：报告结构化目标、成长计划（含"下一周期计划"接口）。

---

## 一、变更总览

| # | 项目 | 变更前 | 变更后 |
|---|---|---|---|
| 1 | 报告结构化目标周期 | 1 年 / 3 年 / 5 年 | **1 个月 / 3 个月 / 5 个月** |
| 2 | 成长计划一轮周期 | 4~12 周（不固定）| **沿 1 → 3 → 5 个月递进**：1 个月档的下一个周期为 3 个月，3 个月档的下一个周期为 5 个月，5 个月档保持 5 个月 |
| 3 | 新周期的定位 | 像是"第二阶段" | **上一周期在时间上的自然延续**：从上一周期**结束之后接着排**，不得与上一周期时间重叠 |

---

## 二、变更 1：报告目标 1/3/5 年 → 1/3/5 个月

### 需要改的地方

1. 报告「结构化目标」里，三个周期的**时间表述与时长**都改为"月"：
   - 原：`1 年目标 / 3 年目标 / 5 年目标` → 新：**`1 个月目标 / 3 个月目标 / 5 个月目标`**
   - 目标文本中的时间词一并改：`"3 年内…"` → **`"3 个月内…"`**（不要出现"年"）
2. 目标下的 `keyActions`（导入后逐条成为成长任务）时长与所属目标一致：**1 / 3 / 5 个月**
3. 档位键（若有）：优先输出 **`1m / 3m / 5m`**（或 `1 / 3 / 5`）；原 `1y / 3y / 5y` 应用侧仍兼容，按同档位处理

### 可直接投喂的提示词片段

```
【周期口径（覆盖原设定）】
本报告中结构化的三个目标周期为「1 个月 / 3 个月 / 5 个月」，不是 1 年 / 3 年 / 5 年。
- 目标名称与描述中的时间表述统一用"月"（例如「3 个月目标」「3 个月内完成…」），禁止出现"年"。
- 每个目标下的 keyActions（关键行动）总时长应与该目标周期一致（1 / 3 / 5 个月），
  并按行动数量把周期合理切分（例如 3 个月目标的 3 条行动可各占 1 个月，允许前后衔接）。
- 档位键优先用 1m / 3m / 5m（或数字 1 / 3 / 5）。
```

## 三、变更 2：成长计划「一轮长度 1 → 3 → 5 个月递进」+ 新周期往后顺延

### 需要改的地方（`提示词-成长下一周期计划接口.md`）

1. **整体周期**：原文的「4~12 周」→ **由请求体里的 `cycleMonths` 决定**（应用侧按上一周期档位算出：1 个月档→3 个月、3 个月档→5 个月、5 个月档→5 个月，约 `cycleMonths × 4.35` 周，允许 ±1 周）
2. **时间定位**：新周期是上一周期的**时间延续**，不是"第二阶段"
   - `next_cycle_plan.startDate` **≥ 上一周期的 `endDate` 次日**
   - `next_cycle_plan.endDate = startDate + cycleMonths 个月 - 1 天`（±1 周可接受）
   - 任务日期必须落在该区间内，且 `startDate ≤ endDate`
3. **表述口径**：不要出现「第二阶段 / 第 N 阶段 / 新一轮阶段」这类说法；用「下一周期 / 接下来两个月」

### 可直接投喂的提示词片段

```
【周期口径（覆盖原设定）】
本周期长度以请求体里的 cycleMonths 为准（1 个月档的下一个周期 3 个月，3 个月档的下一个周期 5 个月，
5 个月档保持 5 个月），约 cycleMonths × 4.35 周，允许 ±1 周浮动。
本次要生成的是上一周期的「下一个周期」，它是时间上的自然延续：
- startDate 必须晚于（不等于）上一周期的 endDate，即从上一周期结束之后接着排；
- endDate = startDate + 2 个月 - 1 天（允许 ±1 周）；
- 所有任务的日期都落在该区间内，且 startDate ≤ endDate；
- 不要写成"第二阶段""第 N 阶段"，用"下一周期"或具体月份区间表述；
- 不要与上一周期的时间区间重叠，也不要重复上一周期已完成且达标的任务。
```

## 四、应用侧（星职）已同步的行为

| 能力 | 现状 |
|---|---|
| 报告导入 | 计划与任务结束日期按 **月** 计算（1/3/5 个月）；档位键兼容 `1m/3m/5m` 与旧的 `1y/3y/5y`（同档位）|
| 前端徽标 | 计划标签显示 **1 个月 / 3 个月 / 5 个月** |
| 下一周期 | 起点取「上一周期 `endDate` 次日」（若已早于今天则取今天）；窗口 = **`cycleMonths`（1→3→5 个月递进）**；模型给的起始日缺失或早于顺延点时，应用侧自动改用顺延日期；任务日期会被夹取进本周期区间 |

> 因此平台侧即使只做到"时间不重叠 + 使用 cycleMonths 窗口"，也不会出现时间错乱的计划；但仍建议按上面片段把口径写进系统提示词，输出会更规整。

## 五、验收清单

- [ ] 报告里三个目标分别为「1 个月 / 3 个月 / 5 个月」，全文无"年"
- [ ] 目标的 `keyActions` 时长与其周期一致
- [ ] 「下一周期计划」返回的 `startDate` **晚于**上一周期 `endDate`
- [ ] `endDate - startDate ≈ cycleMonths 个月`（±1 周）
- [ ] 输出中不含"第二阶段"这类表述，且任务与上一周期时间不重叠
