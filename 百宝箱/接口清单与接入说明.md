## 三、WebSocket 对话通道（`/ws`）

**地址**：H5 页面域名 `https` → `wss` + 路径 `/ws`（单端口同源，无需单独地址）

**客户端事件（4 个）**
```json
HELLO           { "sessionId": "<sid>" }                       // 建连后必须先发
SEND_MESSAGE    { "content": "...", "sessionId": "<sid>", "conversationId": "<cid>", "mediaItems": [] }
CANCEL_RUN      { "runId": "..." }                              // 可选
UI_ACTION       { "surfaceId": "...", "action": "...", "formData": {} }  // 可选
```
> 同一 `sessionId` 连发多条 `SEND_MESSAGE` = 多轮上下文

**服务端事件流（AG-UI，顺序保证）**
```
RUN_STARTED
├─ TOOL_CALL_START / ARGS / END / RESULT     ← searchJobs 双库 RAG（items[].source = 岗位记录 | 能力画像）
├─ TEXT_MESSAGE_START → CONTENT(delta)* → END ← 已剥壳还原的 Markdown 正文
├─ CUSTOM('tbox:card', {id, messageId, cardType, data, status})  ← 结构化卡片结果
└─ RUN_FINISHED { rawEvent.requestId }
```

**实测抓取到的真实事件**
```json
{"type":"RUN_STARTED","threadId":"0c0a800024QBvNifMKS0Cwc4d","runId":"1789652581081_20260917S67S57378765_nsomgy"}
{"type":"RUN_ERROR","threadId":"...","runId":"...","message":"Not Open"}
```

**卡片 data 契约（字段名锁定）**
| cardType | data 结构 |
|---|---|
| `career_pathway` | `{title, phases[{phase, goal, key_actions[], timeline}]}` |
| `scenario_score` | `{scenario: mock_interview\|cross_role_communication\|ai_assisted_office, dimensions{professional, communication, teamwork, problem_solving, learning, innovation, pressure}(0-100), total, comment, suggestions[]}` |
| `weather` | `{city, temp, weather, humidity}`（模板示范） |

**模型输出协议（envelope，三方锁定）**
```
{"response": ...}  |  {"career_pathway": {...}}  |  {"scenario_score": {...}}
```
> WS 上收到的是**解析还原后的产物**；原始信封需用 `messages?format=raw` 获取。

## 四、后端对接四步流（落地到 `AIServiceImpl`）

```
1. POST /api/conversation/create 拿 conversationId
2. 连 WSS /ws：HELLO → SEND_MESSAGE → 消费事件
     · 正文：拼接 TEXT_MESSAGE_CONTENT delta
     · 结果：消费 CUSTOM('tbox:card').value
     · 对账：记录 RUN_FINISHED.rawEvent.requestId
3. 回捞/离线分析：GET /api/conversation/messages?format=raw
4. 断线恢复：凭 sessionId 续会话、凭 conversationId 补历史
```

**与现有后端的映射**（`后端/src/main/java/org/example/web/service/impl/AIServiceImpl.java`）

| 现状（旧自研 AI 服务） | 改造后（百宝箱） |
|---|---|
| `POST /chat` | `POST /api/conversation/create` + WS `SEND_MESSAGE` |
| `POST /chat_with_flux` | WS `/ws` 事件流（`TEXT_MESSAGE_CONTENT` 转 SSE 下发前端） |
| `POST /chat_with_picture_with_RAG` | WS `SEND_MESSAGE` 的 `mediaItems[]` |

> ⚠️ 原设计是「HTTP 转发」，实测发现百宝箱对话是 **WebSocket (AG-UI)** 通道 —— 后端需新增 WS 客户端（Java 可用 `Java-WebSocket` 或 Spring `WebSocketClient`），并把事件流转换为对前端的 SSE。
> 对应 issue：**#15（3-1 后端转发切百宝箱）**，方案需调整为 WS 客户端 + SSE 桥接。

## 七、职业报告接口（异步任务 + 轮询）✅ 已公网实测

> 平台网关（Spanner）对长响应做**完整缓冲**：SSE（`POST /api/report/stream`）从公网物理不可用
> （实测 182s 后返回 `502 Proxy failed after 3 attempts`）。平台已改为**异步任务 + 轮询**，
> 全流程公网实测 **232s 完成、6 段齐全**。SSE 仍保留但只适合内网/本地直连 8000。

### ① 发起（秒回，不会 502）

```
POST {TBOX_API_URL}/api/report
Content-Type: application/json
Authorization: Bearer <TBOX_API_KEY>   # 可选：.env 配了就带

{ "message": "<账号画像上下文 + 用户本次诉求>", "userId": "<我们雪花 ID 字符串>" }
→ 202 {"jobId":"job_...","status":"running"}
```

### ② 轮询（带 `offsets` 拿正文增量，建议 1~2s）

```
GET {TBOX_API_URL}/api/report/jobs/{jobId}?offsets={"profile_analysis":1024,"career_exploration":860}
→ {"status":"running",
   "currentAgent":"career_exploration",
   "agentsDone":["profile_analysis"],
   "deltas":[{"agent":"career_exploration","data":"增量文本…"}],
   "segmentChars":{"profile_analysis":2763,"career_exploration":860},
   "progressChars":3828}
```

> `offsets` = 客户端**每个智能体已读到的字符位置**；服务端据此切片返回增量 `deltas`（不重不漏）。
> 客户端把 `data` 按 `agent` 追加到本地缓冲，并把新的已读长度作为下一次 `offsets` 回传。

### ③ 完成

```
→ {"status":"done","agents":[6 段顺序 key],"reportId":"6aae4b35…",
   "reportName":"职业规划报告 · …",
   "content":{"agents":[{key,name,content}×6],"fullText":"..."}}
```

### 关键约束

- **总耗时约 160~232s**；`running` 期间 `currentAgent` 逐段推进、`progressChars` 实时增长
- **无需 keepalive/心跳**：轮询天然规避网关缓冲
- `reportId` = 平台 Appwrite 行 `$id`，可能为 `null`
- 平台自动落库并把该用户"上一份报告"注入下一次提示词（做进步对比）

### 后端落地（本仓库）—— 前端 start + 轮询，刷新可续

> 关键：任务在**平台侧独立运行**，与浏览器连接无关；后端只做代理与落库，
> 所以前端把 `jobId` 存 localStorage，刷新/切页后继续轮询即可恢复。

| 步骤 | 本仓库 |
|---|---|
| ① 起任务 | `POST /api/career-report/start` `{user_id, content, target_job?}` → `{jobId}`（内部 `TboxAgentService.startReportJob` → 平台 `POST /api/report`）|
| ② 轮询 | `GET /api/career-report/jobs/{jobId}?offsets={...}` → `{status,currentAgent,agentsDone,deltas,segmentChars,progressChars}`（内部代理平台，并把 `offsets` 透传）|
| ③ done | 接口在首次 done 时按 `content.agents` **落库我们 MySQL**（`career_report` + `career_report_history`，`jobId` 幂等只写一次），返回我们的 `reportId` + `platformReportId` + `content` |
| 前端 | `/multi-agent`：每 1.5s 带 `offsets` 轮询 → 把 `deltas[].data` 按 agent 追加到卡片缓冲，**本地 30ms 均匀打字机实时呈现**；done 时用 `content.agents[].content` 校准；`jobId` 存 localStorage，`onMounted` 自动续跑 |

- 说明：平台 `done` 帧的顶层 `agents` 字段为 `null`，**6 段内容在 `content.agents[]`**（`key/name/content`）。
- 平台运行期间通过 `deltas` 提供**正文增量**（按 `offsets` 切片）；前端对每批 delta 再做 30ms 本地均匀播放，即可得到接近真流式的逐字体验。

## 九、报告「取消」与「删除」接口 ✅ 已上线（平台 8e2a7dc + ffd8fdf，验收 1–7 全绿）

> 报告类接口统一鉴权约定：平台配置 `REPORT_API_TOKEN` 后，调用需带 `X-Report-Token` 头（未配置则开放）。
> 本仓库通过 `.env` 的 `TBOX_REPORT_TOKEN` 注入。

### ① 取消任务

```
POST {TBOX_API_URL}/api/report/jobs/{jobId}/cancel      # 无需 body
```

| 场景 | 返回 | 行为 |
|---|---|---|
| running | `{"canceled":true,"status":"canceled"}` | abort 立即生效（模型流/检索/排队段全停），**不落库** |
| 已是 canceled | `{"canceled":false,"status":"canceled"}` | 幂等 |
| done | `{"canceled":false,"status":"done"}` | no-op，已落库数据不动 |
| 不存在 | `{"canceled":false,"status":"not_found","message":"..."}` | HTTP 200 |

`GET /jobs/{jobId}` 的 `status` 新增 `canceled` 取值；`progressChars/segmentChars` 冻结在取消时刻。

> ⚠️ 取消是**终态**：canceled 任务不能恢复；重新生成会立刻产出新报告并成为该用户最新一份。

### ② 批量删除

```
POST {TBOX_API_URL}/api/report/delete
{"reportIds":["6aae..."],"userId":"可选，传了则校验归属"}
→ {"deleted":["...","不存在的也计入(幂等)"], "failed":[{"reportId","reason"}]}
```

- 级联删除：主表行 + `hist_<reportId>` 快照 + 指向被删报告的 `career_report_latest` 指针
- `userId` 不符 → `failed: [{reason:"not_found_or_forbidden"}]`
- 行级并发 10，批量秒级完成，不触发网关 60s 超时

### 本仓库对接

| 能力 | 后端 | 前端 |
|---|---|---|
| 随时停止 | `POST /api/career-report/jobs/{jobId}/cancel` → 平台 cancel | 「停止生成」→ 停轮询/打字机、清状态、**不写 MySQL**；轮询遇 `canceled` 也自动收尾 |
| 批量删除 | `POST /api/career-report/batch-delete` → 我们侧**逻辑删除** + 平台侧**物理删除**（带 `userId` 校验）；平台失败**不阻塞**，返回 `failed/skipped` | 个人中心「管理」多选 / 全选 / 删除选中；结果提示平台未删数与历史跳过数 |

- 需 `career_report.platform_report_id`（迁移 **006**）；无该字段的历史报告仅本地删除。
