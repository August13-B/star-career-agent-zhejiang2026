  → 默认 presented：answer 还原文 + cards[]

## 三、WebSocket 对话通道（`/ws`）

**地址**：H5 页面域名 `https` → `wss` + 路径 `/ws`（单端口同源，无需单独地址）

**客户端事件（4 个）**
```json
HELLO           { "sessionId": "<sid>" }                       // 建连后必须先发
SEND_MESSAGE    { "content": "...", "sessionId": "<sid>", "conversationId": "<cid>", "mediaItems": [] }
CANCEL_RUN      { "runId": "..." }                              // 可选
UI_ACTION       { "surfaceId": "...", "action": "...", "formData": {} }  // 可选
```
> 同一 `sessionId` 连发多条 `SEND_MESSAGE` = 多轮上下文

**服务端事件流（AG-UI，顺序保证）**
```
RUN_STARTED
├─ TOOL_CALL_START / ARGS / END / RESULT     ← searchJobs 双库 RAG（items[].source = 岗位记录 | 能力画像）
├─ TEXT_MESSAGE_START → CONTENT(delta)* → END ← 已剥壳还原的 Markdown 正文
├─ CUSTOM('tbox:card', {id, messageId, cardType, data, status})  ← 结构化卡片结果
└─ RUN_FINISHED { rawEvent.requestId }
```

**实测抓取到的真实事件**
```json
{"type":"RUN_STARTED","threadId":"0c0a800024QBvNifMKS0Cwc4d","runId":"1789652581081_20260917S67S57378765_nsomgy"}
{"type":"RUN_ERROR","threadId":"...","runId":"...","message":"Not Open"}
```

**卡片 data 契约（字段名锁定）**
| cardType | data 结构 |
|---|---|
| `career_pathway` | `{title, phases[{phase, goal, key_actions[], timeline}]}` |
| `scenario_score` | `{scenario: mock_interview\|cross_role_communication\|ai_assisted_office, dimensions{professional, communication, teamwork, problem_solving, learning, innovation, pressure}(0-100), total, comment, suggestions[]}` |
| `weather` | `{city, temp, weather, humidity}`（模板示范） |

**模型输出协议（envelope，三方锁定）**
```
{"response": ...}  |  {"career_pathway": {...}}  |  {"scenario_score": {...}}
```
> WS 上收到的是**解析还原后的产物**；原始信封需用 `messages?format=raw` 获取。

## 四、后端对接四步流（落地到 `AIServiceImpl`）

```
1. POST /api/conversation/create 拿 conversationId
2. 连 WSS /ws：HELLO → SEND_MESSAGE → 消费事件
     · 正文：拼接 TEXT_MESSAGE_CONTENT delta
     · 结果：消费 CUSTOM('tbox:card').value
     · 对账：记录 RUN_FINISHED.rawEvent.requestId
3. 回捞/离线分析：GET /api/conversation/messages?format=raw
4. 断线恢复：凭 sessionId 续会话、凭 conversationId 补历史
```

**与现有后端的映射**（`后端/src/main/java/org/example/web/service/impl/AIServiceImpl.java`）

| 现状（旧自研 AI 服务） | 改造后（百宝箱） |
|---|---|
| `POST /chat` | `POST /api/conversation/create` + WS `SEND_MESSAGE` |
| `POST /chat_with_flux` | WS `/ws` 事件流（`TEXT_MESSAGE_CONTENT` 转 SSE 下发前端） |
| `POST /chat_with_picture_with_RAG` | WS `SEND_MESSAGE` 的 `mediaItems[]` |

> ⚠️ 原设计是「HTTP 转发」，实测发现百宝箱对话是 **WebSocket (AG-UI)** 通道 —— 后端需新增 WS 客户端（Java 可用 `Java-WebSocket` 或 Spring `WebSocketClient`），并把事件流转换为对前端的 SSE。
> 对应 issue：**#15（3-1 后端转发切百宝箱）**，方案需调整为 WS 客户端 + SSE 桥接。

## 七、职业报告专用接口（`POST /api/report/stream`，SSE）

> 该接口由平台提供，**平台侧自行串行编排 6 个智能体并逐段打 `agent` 标签**，
> 因此后端**不再需要** `<<<AGENT:>>>` 段标记协议与 `AgentMarkerParser`（已随本轮改造移除）。

### 请求

```
POST {TBOX_API_URL}/api/report/stream
Content-Type: application/json
Accept: text/event-stream
Authorization: Bearer <TBOX_API_KEY>   # 可选：.env 配了就带，没配不带

{ "message": "<账号画像上下文 + 用户本次诉求>", "userId": "<我们雪花 ID 字符串>" }
```

### 响应帧（全部 `data:{json}\n\n`）

| 帧 | 字段 | 说明 |
|---|---|---|
| 段落增量 | `agent`、`data` | `agent` ∈ 固定 6 个 key，严格按序；`data` 为增量文本，按 key 分组拼接 = 完整章节 |
| 完成 | `done`、`agents`、`reportName`、`reportId` | `reportId` = Appwrite 行 `$id`，可能为 `null` |
| 失败 | `error` | 任意环节失败 → `data:{"error":"文案"}` 后关闭 |

固定顺序：`profile_analysis → career_exploration → goal_setting → path_planning → action_planning → report_composition`

### 关键约束

- **边界由后端程序决定**：`agent` 字段变化 ⟺ 上一个智能体已彻底结束（前端只需对比 key 变化）
- **总耗时 160~185s**；某段内可能 20~30s 无新帧（在调 `searchJobs`），**不是断流**
- **无 keepalive 帧**：网关空闲超时需 ≥60s（本地 `nginx` 已设 300s；后端 `report-timeout-seconds` 默认 360s）
- **断连即作废**：连接关闭 → 平台立刻 abort（不落库、不下发 `done`），无断点续传
- **平台自动落库**：`career_report` + `career_report_history`，并自动把该用户"上一份报告"注入下一次提示词（做进步对比）

### 后端落地（本仓库）

- `TboxAgentServiceImpl.reportStream(userId, message)`：调平台 SSE 并转发帧（`ServerSentEvent<String>`）
- `CareerReportController.generateReportStream`：拼 `message`（画像上下文）→ 透传 → `done` 帧时**另存一份到我们 MySQL**（`career_report` + `career_report_history`），并把我们的 `reportId` 回填下发（平台 `reportId` 存为 `platformReportId`）
- 前端 `/multi-agent`：按 `agent` 变化推进卡片状态，`done` 显示我们的 `reportId/reportName`

## 八、对话流式接口（`POST /api/chat/stream`，SSE）——**待平台提供**

> ⏳ 平台尚未提供该接口，契约见 [`提示词-对话流式接口.md`](./提示词-对话流式接口.md)（可直接交给平台侧实现）。

| 项 | 内容 |
|---|---|
| 请求 | `{ message, userId, conversationId? }`（不传 `conversationId` = 新会话，传 = 续接） |
| 帧 | `{"delta":"..."}`* + `{"type":"tool","name":...,"status":"start\|end"}` + `{"done":true,conversationId,messageId}` + `{"error":"..."}` |
| 用途 | **纯文本多轮对话**（取代 WS 作为默认文本通道）；图片对话仍走 `WS /ws` |
| 后端开关 | `TBOX_CHAT_CHANNEL=http`（默认）／`ws`（平台未就绪时兜底）；超时 `TBOX_CHAT_TIMEOUT_SECONDS=180` |

> 在平台提供该接口前，把 `TBOX_CHAT_CHANNEL` 设为 `ws` 即可回退旧链路（文本走 WS）。
