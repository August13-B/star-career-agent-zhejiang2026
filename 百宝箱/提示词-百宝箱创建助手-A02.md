## 一、提示词全文（直接整段复制粘贴给创建助手）

```

- **只新增接口**，不要新建应用、不要改动现有的人设、知识库、对话链路与报告链路

════════════════════════════════════════

  POST /api/training/interview        接口 1

════════════════════════════════════════

════════════════════════════════════════
■ 入参（后端会这样调用，字段名不可改）
{
  "mode": "ask" | "evaluate",          // ask=提问/追问；evaluate=评分
  "prompt": "<后端已构建好的完整任务指令文本>",
  "scenario": "mock_interview | cross_role_communication | ai_assisted_office"
}
说明：`prompt` 里已包含当前阶段、当前身份、本题原文、难度、固定材料、历史回答；
evaluate 时还会附带「冻结证据目录」（编号形如 A3E12）。**以这个 prompt 为准执行，不要自行改写阶段或题目。**

■ 出参
- mode = "ask"      → 只回**纯文本**（该阶段要说的话，100–260 字），例如：
    { "reply": "…" }
    也允许直接返回纯文本 body（二者其一即可，请在交付时说明采用哪种）
- mode = "evaluate" → 只回**评分 JSON 本体**：
    {
      "training_evaluation": {
        "scenario": "…",
        "templateVersion": "…",
        "rubricVersion": "…",
        "dimensions": { "<本场景 4 个维度键>": 0 },
        "evidence": [ { "dimension": "<维度键>", "evidenceId": "A1E1" } ],
        "comment": "≤300 字",
        "suggestions": [ "≤100 字" ]
      }
    }

■ 流式（可选但推荐）
若平台支持，请让接口支持流式（SSE 或沿用现有 WS），事件里：
- ask 阶段逐块推送纯文本增量
- evaluate 阶段最后一次性给出完整评分 JSON
并在交付时说明：流式地址、事件名、结束标志。若不便实现，返回一次性 JSON 也可，请注明。

■ 鉴权：沿用应用现有方式（可带 `Authorization`），请说明是否必填。

════════════════════════════════════════
【三个接口的共用行为：提问 → 追问 → 评分】
════════════════════════════════════════
1) 提问：按 `prompt` 指定的阶段给场景背景与该阶段题目，**一次只问一题**
2) 追问：基于用户**上一题的实际回答**深挖（引用其原话或结论），不建议、不代写、不给参考答案
3) 评分：仅在 `mode="evaluate"` 时输出评分 JSON；ask 阶段**绝不评分、绝不输出 JSON**

■ 提问与追问要求
- 每轮 100–260 字，结构清楚；可给结构提示（如"请按 用途/职责/难点/结果 四段说"），**不得代写答案**
- 难度 entry 可给结构与要点提示；难度 standard 由用户自主分析，仅在明显缺项时指出缺哪一项
- 用户回避关键取舍时，用该阶段身份继续追问，不要放过
- 若 `prompt` 说明「所有阶段已回答完毕…」：只做收尾提醒（提醒保存作品 + 提示"模拟经历不要写入简历"），不再提问

■ 纪律（反偏见，必须遵守）
- 不以表达风格、打字速度、口语流利度、术语数量评分
- 不鼓励隐瞒风险、跳过回归测试、无条件加班、伪造一致同意
- 用户明确说"没有相关经历"并按要求使用假设案例练习时，**不因此扣分**，只评其推理与结构

■ 三个接口各自的身份与阶段剧本（此处即为各接口的系统提示词内容）

 2 结合刚才的案例，追问一个具体技术取舍，要求说明为什么这样设计、考虑过什么替代方案以及如何验证。
 3 假设报名接口在用户重复点击时写入重复记录，请说明你的排查步骤、幂等设计以及如何验证并发情况下的正确性。
 4 产品临时增加导出需求，而测试认为现有版本还有阻断缺陷。你如何澄清诉求、与不同岗位协商交付范围？

【接口 2 · 跨岗位沟通】身份：跨岗位协作训练官，按阶段分别扮演产品 / 开发 / 测试。固定背景（虚构，数字与约束不得改）：

════════════════════════════════════════

    professional=专业技能 | communication=沟通能力 | teamwork=团队协作 | problem_solving=问题解决
    learning=学习能力 | innovation=创新能力 | pressure=抗压能力

    接口 2 → communication 35% / teamwork 30% / problem_solving 25% / learning 10%
    接口 3 → professional 25% / problem_solving 30% / learning 25% / innovation 20%

   - **基线 60** = 基本达标（画像缺项默认值也是 60）
   - 锚点校准：专业技能 入门≈55 / 了解≈65 / 熟练≈80 / 精通≈92；软实力按表现得分率百分比

   - `total` 不用输出（后端按权重重新计算并覆盖）

四、评语与建议
   - comment ≤300 字：结论 → 依据（引用证据）→ 薄弱点
   - suggestions 1–3 条，每条 ≤100 字，具体、可操作、可检验
   - 若 prompt 写明"某阶段超时提交"：评语如实提及，但不额外惩罚，也不得虚构"未超时"的表现

════════════════════════════════════════
【输出格式规范】
════════════════════════════════════════
1. ask：只输出纯文本（或 {"reply":"…"}），不要 JSON 评分、不要说明性前后缀
2. evaluate：只输出 `training_evaluation` JSON 本体，不加 ``` 围栏、不加说明文字

5. **评语与建议中不要使用英文双引号**（如需强调请用「」）——在 JSON 字符串里写裸引号会让整个评分 JSON 断裂，
   后端只能判「待复核」（本仓库已加裸引号兜底修复，但仍请从源头避免）
6. **技术深度**（面试接口）：任务指令给出了目标岗位的**关键技能与职责描述**，整场至少一半题目必须是**该岗位的技术题**，

5. 允许 Markdown（### / **加粗** / - 列表）；前端会去掉标记按纯文本展示

## 二、接口已交付（按实测契约核对）

创建助手交付的三个训练接口，与本文档要求**逐项对齐**：

| 项 | 约定 | 交付实测 |
|---|---|---|
| 路径 | `POST /api/training/{interview\|communication\|office}` | ✅ 一致 |
| 入参 | `{mode: ask\|evaluate, prompt, scenario?}` | ✅ 一致（`prompt` 上限 10 万字符；`scenario` 不符 → 400，防误路由）|
| 出参 | ask → `{"reply":"…"}`；evaluate → `{"training_evaluation":{…}}` | ✅ 一致 |
| 错误码 | — | 400 参数/scenario 不符；401 token 不符；502 评分 JSON 无法提取/模型失败 |
| 流式 | 可选 | 暂不对外流式，**一次性 JSON**（模型侧内部流式聚合）；前端“正在准备问题…”会在结果到达时一次性显示 |
| 鉴权 | 可带 token | 默认开放；配置 `TRAINING_API_TOKEN` 后必带 `X-Training-Token`（与 `TBOX_API_KEY` 无关）|
| 隔离 | 不影响主链路 | 不走 Mastra；不写会话历史、不进 WS/envelope/卡片链路、不碰知识库；仅 `router.ts` +1 行挂载 |
| 容错 | 兼容包裹 | 评分被 ``` 围栏或 `{"response":…}` 包裹会自动解包；维度/证据编号**不在接口侧校验**，权威校验在后端 `TrainingScoreValidator`，提取失败 → 502 交后端判失败 |

## 三、后端接入状态

| 环节 | 状态 |
|---|---|
| 后端按场景路由到对应接口（`TboxScenarioGateway`） | ✅ 已实现：`scenario` → 接口路径；**三个变量留空则自动回退旧 WS 会话链路** |
| 请求体构造 | ✅ `{mode: ask\|evaluate, prompt, scenario}`；`prompt` = 后端冻结的任务指令（含阶段/身份/题目/材料/历史；评分时含冻结证据目录）|
| 评分解析 | ✅ `evaluate` 的 `training_evaluation` 交给 `TrainingScoreValidator` 做权威校验（维度必须等于本场景 4 维、证据编号须在目录内、版本号一致）；不合规 → 该次评分“待复核”，不展示分数、不更新画像 |
| 容错 | ✅ 围栏/`{"response":…}` 包裹自动解包；接口不可用/超时 → 提示可重试（回答已保存）|
