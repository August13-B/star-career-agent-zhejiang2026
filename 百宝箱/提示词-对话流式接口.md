# 百宝箱提示词 · 对话流式接口（`POST /api/chat/stream`）

> 用途：把本文件整段交给**蚂蚁百宝箱企业版**的「AI 创建 / 接口开发」助手，或提交给平台侧工程师，
> 在现有应用上**新增一个对话流式 HTTP SSE 接口**——对标平台已有的报告接口 `POST /api/report/stream`。
> 目标：让第三方后端（本项目 Spring Boot）在**纯文本多轮对话**时走 HTTP SSE，不再依赖 WebSocket。
> 生成时间：2026-09-19

---

## 一、为什么需要这个接口（背景）

- 当前应用只有 WebSocket 对话通道 `WSS /ws`（AG-UI 事件流）。它可用于多模态（图片），但接入成本高（自建 WS 客户端 + 事件桥接）。
- 应用已有 `POST /api/report/stream`（SSE，平台侧编排多智能体并逐段打 `agent` 标签），接入很干净。
- 现在需要一个**同风格的对话 SSE 接口**，用于纯文本问答：**逐字流式**、**支持多轮续接**、**可暴露检索状态**。

## 二、接口需求（必须严格遵守）

### 1. 基本约定

```
POST /api/chat/stream
Content-Type: application/json
Accept: text/event-stream
响应头：
  Content-Type: text/event-stream; charset=utf-8
  Cache-Control: no-cache
  X-Accel-Buffering: no
鉴权：可选 Authorization: Bearer <TBOX_API_KEY>（与 /api/report/stream 保持一致：配了就校验，没配不强制）
```

### 2. 请求体

```json
{
  "message": "用户本轮输入（必填，空 → HTTP 400 普通 JSON 错误，不是 SSE）",
  "userId": "调用方用户标识（可选，用于平台侧会话归属与落库）",
  "conversationId": "可选：不传 = 新建会话；传入 = 续接该会话的多轮上下文"
}
```

> `message` 由调用方拼好：**已包含该用户的画像/资料上下文 + 本轮问题**（调用方 MySQL 的实时画像平台侧没有，故由调用方注入）。

### 3. 响应帧（全部 `data:{json}\n\n`）

| 帧 | 字段 | 说明 |
|---|---|---|
| 增量文本 | `delta` | 逐字/逐块下发正文；**必须流式，不要等全部生成完再一次性下发** |
| 工具/检索状态 | `type`、`name`、`status` | `{"type":"tool","name":"searchJobs","status":"start"\|"end"}`；用于前端在"无文字空窗期"显示「正在检索岗位知识库…」。可选但强烈建议（检索可能耗时 20~30s） |
| 完成 | `done`、`conversationId`、`messageId`、`requestId` | `{"done":true,"conversationId":"...","messageId":"...","requestId":"..."}`；`conversationId` 用于调用方保存映射以便下次续接 |
| 失败 | `error` | `{"error":"可读文案"}`，随后关闭连接 |

**帧顺序示例：**

```
data:{"type":"tool","name":"searchJobs","status":"start"}
data:{"delta":"根据你的"}
data:{"delta":"专业背景与"}
data:{"delta":"目标岗位…"}
data:{"type":"tool","name":"searchJobs","status":"end"}
data:{"delta":"\n\n建议你…"}
data:{"done":true,"conversationId":"20260919AbCdEf123456","messageId":"msg_0001","requestId":"req_0001"}
```

### 4. 多轮语义（关键）

- **不传 `conversationId`**：平台新建一个会话，自动落库，并在 `done` 帧返回新的 `conversationId`。
- **传入 `conversationId`**：平台续接该会话，**自动注入该会话的历史上下文**（调用方无需自己拼历史）。
- 同一 `userId` 下可有多个 `conversationId`；`conversationId` 是会话的唯一标识。
- 平台需落库（会话 + 消息），并支持按 `conversationId` 回捞（复用现有 `/api/conversation/messages` 亦可）。

### 5. 其它约束（与 `/api/report/stream` 对齐）

- **逐字流式**：`delta` 必须是增量；检索期间允许短暂无帧（建议用 `tool` 状态帧填充）。
- **断连即作废**：调用方断开连接 → 平台立即 abort 本轮（可不下发 `done`）。
- **无 keepalive 帧**：如网关有空闲超时，请放宽（本项目网关已 ≥300s）。
- **不做幂等**：每次调用都是一次新回答；重试由调用方控制。
- **图片不支持**：本接口只处理纯文本；图片能力继续由现有 `WSS /ws`（`mediaItems[]`）承担。
- **数据互不污染**：本接口不应触发"职业报告"流水线（报告走 `/api/report/stream`）。

## 三、验收用例

| # | 用例 | 期望 |
|---|---|---|
| 1 | `POST` 空 `message` | HTTP 400 + JSON（非 SSE） |
| 2 | 不传 `conversationId` | `delta`* → `done`（含新 `conversationId`、`messageId`） |
| 3 | 传上一轮 `conversationId`，问"我刚才说了什么" | 回答能体现上一轮内容（平台已注入历史） |
| 4 | 问需要查岗位的问题 | 出现 `tool/searchJobs/start` 与 `end` 帧 |
| 5 | 中途断开连接 | 平台中止，不产生半截脏数据 |
| 6 | 长回答 | `delta` 帧连续、前端可逐字渲染，而非最后一次性到达 |

## 四、给应用智能体的人设 / 回答要求（补充）

> 以下内容请写入应用的**系统提示词/人设**（若与现有配置冲突，以"不破坏多智能体报告流程"为前提）：

```
你是「星职 · AI 职业导航助手」，面向在校大学生与职场新人。
- 结论先行、条理清晰、给出可执行动作；不空泛鼓励、不绝对承诺（不说"保证拿到 offer"）。
- 回答岗位/薪资/行业类问题必须以知识库检索结果为准，不得编造；检索不到就如实说明。
- 调用方会在 message 里附带【用户账号下的画像数据】。若其中有内容，请优先结合该画像作答；
  若画像缺失或标注"未填写/暂无数据"，用通用知识作答，并在回答末尾**礼貌提醒**用户
  去"个人中心"补全画像（一句话即可，不要反复强调）。
- 涉及心理状态时保持专业克制，必要时建议寻求线下专业支持。
- 不索取或复述用户身份证号、手机号等敏感信息。
- 全文简体中文；不要在正文里输出 JSON 信封（如 {"response":...}）。
```

## 五、交付物

- 上述 `POST /api/chat/stream` 可用（含多轮、流式、tool 状态帧、错误帧）
- 在预览/已发布环境的连通自检：
  ```bash
  curl -N -X POST "$APP_API_URL/api/chat/stream" \
    -H 'Content-Type: application/json' -H 'Accept: text/event-stream' \
    -d '{"message":"你好，请用一句话介绍你自己","userId":"test"}'
  ```
  期望：先收到若干 `data:{"delta":...}`，最后 `data:{"done":true,...}`。

## 六、本项目后端将如何对接（供平台侧参考）

- 纯文本对话：后端调用本接口，把 `delta` 转成对前端的 SSE；`done` 时把 `conversationId/messageId` 存入
  `ai_conversation.tbox_conversation_id` / `ai_message.tbox_message_id`，并另存一份消息到本项目 MySQL（供前端列表/历史）。
- 带图片对话：仍走现有 `WSS /ws`（`mediaItems[]`），本接口不涉及。
- 鉴权：本项目 `.env` 配了 `TBOX_API_KEY` 就带 `Authorization: Bearer ...`，没配不带。
