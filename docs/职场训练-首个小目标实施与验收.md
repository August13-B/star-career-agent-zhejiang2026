# 职场训练：首个小目标实施与验收

> 更新：后续三场景完整实现已完成，请以 [职场训练完整使用说明](职场训练-完整实现与使用说明.md) 为当前状态。本文保留该阶段记录。
更新日期：2026-09-24。基础版本：`origin/develop@2703ae0`。开发分支：`feat/interview-training`。

本次实现的是 **Java 后端实习岗模拟面试** 的完整首个闭环。跨岗位沟通、AI 辅助办公和能力画像联动属于后续阶段，大厅明确标为未开放。总体三场景方案见 [职场场景模拟训练设计](职场场景模拟训练设计.md)。

## 1. 现在可以怎样使用

打开 `http://localhost:5173/training`，或点击左侧「职场训练」。使用自己的账号登录后：

1. 点击「开始模拟面试」，阅读目标及四个评分维度，等待面试官提出第一题。
2. 在「我的回答」中输入内容，点击「提交回答」。换行不会发送，最多 4000 字。
3. 面试官围绕当前回答追问，六题依次覆盖项目职责、技术取舍、幂等排障、岗位协作、上线风险和复盘行动。
4. 回答保存到服务器；输入停止约 700 毫秒后保存草稿，离开路由前也会保存。看到「草稿已保存」后可刷新恢复。尚未保存时关闭或刷新页面会触发浏览器离页提示。
5. 生成过程中可以切到其他页面；返回训练大厅，点击原训练记录继续。对话任务由后端执行，切页不会取消任务。
6. 回答完六题后点击「结束并评分」，确认提交。也可以至少回答一题后提前结束，获得标明为「阶段性训练反馈」的评价。
7. 查看四维得分、总分、原文依据及改进建议。点击依据可定位到对应回答。训练页和对话区域分别支持滚动。
8. 平台超时或报错时点击「重试本次任务」，保留原回答；最多两次重试。主动「取消本次训练」后不可继续，但已保存问答可以回看。

如果评价显示「待复核」，意味着模型缺少字段、证据、正确版本或有效分数。系统保留问答与原始结果，但不展示该次未经验证的分数；用户可以回看问答并重新开始训练。当前尚无人工复核后台。

本阶段评分仅用于本次练习反馈，**不会更新个人能力画像、成长计划，也不会影响实际录用判断**。

## 2. 实际实现结构

| 位置 | 用途 |
| --- | --- |
| `前端/src/views/TrainingView.vue` | 训练大厅、工作台、历史、草稿、轮询、评价和证据定位 |
| `前端/src/utils/trainingApi.js` | 请求封装、Bearer 归一、错误与任务状态处理 |
| `前端/src/router/index.js`、`前端/src/App.vue` | `/training`、`/training/:sessionId` 及侧边栏入口 |
| `后端/.../controller/TrainingController.java` | 校验参数、读取 JWT 用户、返回 HTTP 与业务状态 |
| `后端/.../service/training/TrainingService.java` | 会话事务、幂等提交、状态机、草稿版本、持久化和评分请求 |
| `TrainingWorker.java` | 后台执行、有限队列、取消、失败重试及重启恢复 |
| `TboxScenarioGateway.java`、`TrainingPlatformEvents.java` | 百宝箱 HTTP 建会话、WebSocket 事件接入，保留结构化结果 |
| `TrainingScoreValidator.java` | 版本、四维分数、回答归属和原文证据校验；重新计算总分 |
| `TrainingEvidenceCatalog.java` | 为本人回答的连续原文片段生成稳定编号，供模型选择，后端还原原文 |
| `TrainingContentCipher.java` | 用现有 AES_KEY 和每次随机 nonce，对训练内容进行 AES-GCM 加密 |
| `后端/.../mapper/TrainingMapper.java` | 有完整 SQL 注解的 MyBatis 数据访问 |
| `后端/src/main/resources/training/interview_backend_intern.v1.json` | 六题目标、公开维度、评分权重及评价规则 |
| `数据库/migrations/010_training_interview.sql` | 幂等新增四张训练表；完整建库脚本同步了结构 |
| `scripts/training_smoke.py` | 真实平台六题验收，用新建的隔离测试账户测试并清理其本地数据 |

以上后端 Java 路径中的 `后端/...` 指 `后端/src/main/java/org/example/web`。同目录的服务文件均位于 `service/training/`。

四张新表分别是：

- `training_session`：所属用户、模板、状态、回答数、会话版本及草稿版本。
- `training_turn`：按顺序持久化的用户回答与面试官回复，包括未完成状态。
- `training_run`：每次 start / turn / evaluate 执行，保存冻结输入、请求去重标识、尝试次数及原始结果。
- `training_evaluation`：通过校验的评价或待复核原因，每个会话最多一条最终评价。

当前用「后台任务 + 快照轮询」实现恢复：生成中约 1.2 秒轮询，空闲约 5 秒轮询。所有 Long ID 通过接口传字符串。没有新增未经实现的通用作品表、能力应用表或跨场景评分接口。

## 3. 已实现接口

基础前缀为 `/api/training`，需要现有登录 JWT。成功业务码仍为 `10001`；错误沿用 `10002`，训练错误另含 `data.errorCode`。接口不接收客户端指定的 userId。

| 方法及路径 | 参数 / 请求体 | 行为 |
| --- | --- | --- |
| GET `/templates` | 无 | 返回当前开放的面试模板 |
| POST `/sessions` | `templateId, clientRequestId` | HTTP 201，创建训练并排队首题 |
| GET `/sessions` | `offset=0, limit=20`（最多 50） | 返回本人的分页训练记录 |
| GET `/sessions/{id}` | ID 字符串 | 一致快照：问答、草稿、版本、任务、评价、模板 |
| POST `/sessions/{id}/turns` | `content, clientRequestId, expectedVersion` | HTTP 202，保存回答并开始下一次回复 |
| PUT `/sessions/{id}/draft` | `content, expectedVersion` | 更新草稿；这里的版本是 `draftVersion` |
| POST `/sessions/{id}/finish` | `clientRequestId, expectedVersion` | HTTP 202，冻结训练并开始评分 |
| GET `/sessions/{id}/evaluation` | 无 | 读取本次评价，尚未生成时为 null |
| GET `/runs/{id}` | 无 | 返回任务状态、尝试次数和可读错误 |
| POST `/runs/{id}/retry` | `expectedAttempt` | HTTP 202；仅重试最新失败任务，重复请求不会重复启动 |
| POST `/sessions/{id}/cancel` | 无 | 显式取消，重复取消幂等 |

`clientRequestId` 为 8–80 位字母、数字、下划线或短横线，前端使用 UUID。同一请求标识及相同输入返回原执行；不同内容复用标识返回冲突。`expectedVersion` 在回答和完成接口中取会话 `version`。每个用户同时只允许一个 queued/running 执行。

常见状态：未登录 401、非本人记录 404、版本或状态冲突 409、输入/模板不合法 400 或 422、已有运行任务 429、平台异常 502、配置/加密问题 503。

## 4. 平台接入与评分协议

复用已有配置，不要求你再填一套模型密钥：

`GET /api/tbox/session` → `POST /api/conversation/create` → `WS /ws` 的 HELLO / SEND_MESSAGE → TEXT_MESSAGE_CONTENT / CUSTOM → RUN_FINISHED。

每次执行使用独立平台会话，后端显式传入本次冻结的问答。RUN_ERROR、空响应及未收到 RUN_FINISHED 的断开均按失败处理。

实测发现，平台旧 `scenario_score` 卡片会转换成七维旧格式，丢掉本功能需要的版本与 evidence。新训练评分因此使用平台已有 `response` 文本通道：外层为 `{"response":"内部 JSON 的字符串"}`，内部内容如下。后端严格解析，不从 Markdown 摘取看似分数的文字。

```json
{
  "training_evaluation": {
    "scenario": "mock_interview",
    "templateVersion": "interview_backend_intern.v1",
    "rubricVersion": "interview_rubric.v1",
    "dimensions": {"professional": 80, "communication": 70, "problem_solving": 90, "pressure": 60},
    "total": 77,
    "comment": "基于具体回答的评语",
    "suggestions": ["具体、可验证的下一次练习建议"],
    "evidence": [
      {"dimension": "professional", "evidenceId": "A1E1"}
    ]
  }
}
```

示例 evidence 只展示一条的格式，实际必须覆盖四个维度。后端将已提交的用户回答划分为不超过 350 字的连续原文片段，附上 `A1E1` 等稳定编号；模型只能从该目录选择相关 evidenceId，后端拒绝未知编号，并还原为页面使用的 `sourceType=turn, sourceId=原消息ID字符串, quote=原文`。不要求模型重抄长 ID 和原文，避免转录误差；不从面试官发言生成目录，也不生成新的证据内容。编号存在仅证明引用来源有效，不能替代对证据与评分是否相关的语义复核。评分提示提供完整四条证据模板。后端按 30% / 30% / 25% / 15% 重新计算总分，不直接采用模型给出的 total。

原始文本和卡片加密保存在 `training_run.raw_result`。兼容平台直接返回 `sourceType/sourceId/quote` 的格式，但仍要求归属正确且逐字匹配。旧卡片只有在包含全部新协议字段且通过校验时才会被接受。当前未修改已有普通对话、职业报告的接入和展示协议。

## 7. 当前边界与下一步

- 首批仅一个固定岗位模板、文字交互；模型输出仍可能不满足证据协议，失败时展示待复核。这不是对模型语义正确性和评分公平性的证明。
- 后台执行目前按单 Spring Boot 实例设计。后端重启时，queued 任务恢复；running 任务标为可重试失败。多实例部署前需要数据库租约/分布式任务调度，不能直接并行启动多个 Worker。
- 本阶段取消会关闭本地任务并阻止迟到结果落库；平台推理是否立即停止取决于平台 WebSocket 断开处理，没有声称实现平台计费取消。
- 暂未提供训练删除、导出、跨用户管理员复核、画像写入和成长任务加入接口。AES_KEY 是现有训练密文的解密密钥，轮换需要迁移流程。
- 下一小目标在同一持久化框架上实现「跨岗位沟通」：角色任务、分歧协商、确认单及确认单证据；之后实现「AI 辅助办公」的材料核验、作品修订及成果评分。最后再做带来源和幂等保护的画像/成长记录联动。
- 上传前再次 fetch、核对并整合 develop；仅推送功能分支，创建以 develop 为目标的 PR，GitHub CI 全通过后才允许合并。本次没有推送、创建 PR 或合并。
- 开发过程中多次 fetch 成功，基线保持 `2703ae0`；收尾阶段 GitHub 连接重置/超时，最新一次远端检查未成功，不能保证最后成功获取之后远端没有更新。上传前必须恢复连接并再次核对。
