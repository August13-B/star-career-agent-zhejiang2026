## 二、方案文档承诺但【未实现 / 缺失】的部分

> 判定依据：《项目详细方案》《项目介绍PPT》中描述的架构与功能，对照代码逐项核查。
> 结论一句话：**"多智能体协同中枢"与"动态调整方案"整体缺失，SSE 流式只实现了最基础链路，B 端实时化与大数据基建未落地。**

### 2.1 🔴 核心缺失：MOE 多智能体协同中枢（后端）—— 完全未写

方案文档（3.3 章）承诺的**专家混合（MOE）多智能体协同网络**，后端零实现：

| 方案承诺 | 代码现状 |
|---|---|
| 意图路由智能体（Router Agent）：意图分类、模糊意图识别、置信度追问 | ❌ 无。AI 服务只有一个 `AIChatService` 接口 + RAG 检索 |
| 职业教练与人资智能体（Coach & HR Agent）：能力 Gap 诊断书、成功率预测 | ❌ 无。匹配只有简单加权计算，无 AI 诊断、无成功率预测 |
| 成长规划智能体（Planner Agent）：目标拆解、动态排期、计划重构 | ❌ 无。`grow_plan`/`grow_task` 只有表结构与实体，**无任何 Service 实现** |
| 情绪感知与韧性干预智能体（Emotion Agent）：情绪识别、分层干预、预警 | ❌ 无。后端/前端均无情绪相关代码 |
| 共享黑板（Blackboard）+ 冲突消解 + 五重交叉验证 | ❌ 无。无任何编排/黑板/消解代码 |
| 多智能体并行计算与结果融合 | ❌ 无 |

**关键证据**：前端 `MultiAgentView.vue`（"MOE 伴随式智能体协同大屏"）是**纯前端 Mock**——929 行全部为硬编码 HTML 输出 + `sleep()/setTimeout()` 模拟流程，**零 axios/fetch 调用**，不与任何后端交互。评审演示时是"演"出来的，不是真实推理。

### 2.2 🔴 核心缺失：动态调整方案（后端）—— 未写

方案文档（创新点 3、3.3.3）承诺的"目标导向动态成长反馈陪伴系统"：

| 方案承诺 | 代码现状 |
|---|---|
| 计划动态重构（进度变化 / 目标调整 / 情绪不佳时触发计划重排） | ❌ 无 |
| 任务依赖识别、先后顺序安排 | ❌ 无 |
| 动态排期（结合每日可投入时长、学习习惯、知识基础） | ❌ 无 |
| 情绪触发降级任务（中度负面情绪 → 切断高压计划流 → 降级任务） | ❌ 无 |
| 成长数据动态分析、动态调整计划 | ❌ 无 |

### 2.3 🟠 缺失：三层记忆驱动引擎

方案文档（4.2 章）承诺的瞬时 / 短期 / 长期三层记忆：

- ❌ `ChatController` 中 `chatMemory` / `chatMemoryProvider` **全部被注释掉**，会话记忆未接入
- ❌ Redis 滑动时间窗（15-30 天短期行为数据）无实现
- ❌ 短期 → 长期记忆转化（向量化沉淀）无实现
- ❌ 长期记忆唤醒（跨月/跨年召回用户画像）无实现
- ⚠️ 现状：对话历史仅按 `ai_message` 表存储，无分层记忆逻辑

### 2.4 🟠 缺失 / 不完整：SSE 流式输出（只完成最基础链路）

**已实现**：前端 fetch → 后端1 `/send-stream` → AI 服务 `/chat_with_flux`（SseEmitter）→ 前端 `ReadableStream` 逐块读取 → 假流式打字机（`charQueue` + `typeTimer`，Emoji 用 `Array.from` 防乱码）。

**方案承诺但未实现**：

| 方案承诺 | 代码现状 |
|---|---|
| SSE 心跳保活 + 断线自动重连 + 重传丢失数据块 | ❌ 无 |
| 残缺 JSON 符号 / 无效字符剥离 | ❌ 前端仅 `try/catch JSON.parse`，无健壮清洗 |
| 实时 Markdown 解析 | ❌ `formatText` 只是针对 `career_pathway` 等特定字段的正则替换，非通用 Markdown 渲染 |
| 流式过程中图表数据异步渲染（ECharts 边生成边渲染） | ❌ 无 |
| 流式渲染完成后自动持久化到账号（可随时查看/编辑/导出） | ❌ 流式通道不落库（`send-stream` 不保存 ai_message） |
| 流式过程用户可中断 / 失败重试 | ❌ 无 |

### 2.5 🟠 缺失：B 端全局态势感知大盘实时化

方案文档（3.5 章）承诺：

- ❌ WebSocket 实时推送（全后端无 `WebSocket`/`@ServerEndpoint`）
- ❌ RabbitMQ/Kafka 异步削峰队列（pom 无相关依赖）
- ❌ Flink 实时聚合计算
- ⚠️ 现状：`TutorDashboardView.vue`（360 行）为静态/轮询展示，无实时推送通道；后端无对应聚合服务

### 2.6 🟡 方案描述与实际实现不一致（需在省赛材料中修正或补齐）

| 方案宣称 | 实际 |

## 三、国赛 A13 → 省赛 A02 赛题差异（要求发生变动的部分）

### 3.1 赛题对比

| 维度 | 国赛 A13（明杉科技） | 省赛 A02（蚂蚁百宝箱） |
|---|---|---|
| 题目 | 基于 AI 的大学生职业规划智能体 | 面向未来工作的 AI 职业导航或终身学习伙伴系统设计 |
| 目标用户 | 高校学生 | 所有年龄层与职业阶段用户（重点仍含学生） |
| 平台要求 | 无限制，自行选择 | **必须依托蚂蚁百宝箱企业版（b.tbox.cn）开发** |
| 大模型 | 至少一个 LLM | 百灵大模型、通义千问、DeepSeek |
| 协议 | 无要求 | **MCP 协议**（第三方服务对接） |
| 发布渠道 | 无要求 | Web（必选）+ 支付宝小程序 / 微信小程序（可选） |
| 核心闭环 | 画像 → 匹配 → 报告 | 感知 → 认知 → 决策 → 生成 → 执行 → 反馈（全技术闭环） |
| 路径规划 | 短期/中期成长计划 | **3-5 年职业发展路径**，可细化、可调整 |
| 场景模拟 | 无明确要求 | **至少 3 种职场场景模拟训练**（远程协作、AI 辅助办公、跨岗位沟通） |
| 陪伴机制 | 方案中有 Emotion Agent（未实现） | **人机信任与长期陪伴**：情感共鸣、目标监督激励（评分点） |
| 资源整合 | 岗位数据 | **教育、招聘、职业认证等第三方服务整合**（合规前提下 API 对接演示） |
| 伦理要求 | 一般提及 | AI 伦理设计（规避算法偏见、保护隐私、防过度依赖）为**重点加分维度** |
| 数据 | 企业提供 10000 条岗位数据 | 参赛团队自建高校生/职场新人模拟数据 |

## 四、新增功能规格：职场场景模拟训练模块（需求已确认 ✅）

> 本节为**开发 agent 需求规格**：说明要做什么、对接哪些现有代码/表、怎么验收。暂不写代码。

### 4.1 需求来源与决策

- 赛题 A02 硬性要求：**至少 3 种典型职场场景模拟训练模块**（如远程协作、AI 辅助办公、跨岗位沟通）
- 决策（2026-08-15 确认）：在国外包**现有前端基础上新增功能**，不新建系统；**模拟训练结果反哺学生能力画像**，形成"场景模拟 → 能力评分 → 画像提升"闭环，同时为"动态调整方案"（缺口 2.2）提供数据入口

### 4.2 三个模拟场景

| 场景 | 说明 | 主要考核能力维度 | 复用点 |
|---|---|---|---|
| 1. 模拟面试 | 现有 interview_record 雏形扩展为完整模块：岗位相关面试题 + AI 追问 + 逐题评分 + 综合建议 | 沟通能力、抗压能力、专业技能、问题解决 | interview_record 表、AiConversation 对话组件 |
| 2. 跨岗位沟通 | 新增：给定跨部门/跨岗位协作背景（如"后端需要向产品/运营说明技术方案"），用户以角色身份回复，AI 扮演对方角色追问并评估 | 沟通能力、团队协作、问题解决、学习能力 | 对话组件 |
| 3. AI 辅助办公（建议项，可替换） | 新增：给定办公任务（如"用 AI 生成一份竞品分析报告框架"），用户与 AI 工具协同完成并提交产物，AI 评估其提示词/拆解/校验能力 | 创新能力、学习能力、专业技能、问题解决 | 对话组件 |

> 维度命名与 `student_ability_score` 表 10 维字段一一对应（见 6.4）。若团队想换第 3 个场景（如远程协作、向上沟通），替换即可，闭环设计不变。

### 4.3 画像提升闭环（核心设计）

```
进入场景(前端新增页) → 对话/任务式交互(角色扮演) → 用户提交
→ AI 评分(结构化 JSON: 各维度分数 + 评语) → 后端落库:
   ① 更新 student_ability_score（对应维度 + total_score）
   ② 写入 student_ability_score_history（version+1, change_reason="xx场景模拟训练"）
→ 前端雷达图/画像页刷新 → (可选)联动 grow_task 动态调整
```

要点：
- 每次训练后画像**版本 +1**，历史可查（评审可展示"训练前 62 分 → 训练后 68 分"的成长轨迹）
- 评分与画像更新是**异步低侵入**：不阻塞对话，训练结束统一结算
- 画像提升会带动"人岗匹配度"重算 → 报告/雷达图联动（匹配服务已存在）

### 4.4 现有数据结构对接点（已核实）

| 表 | 关键字段 | 用途 |
|---|---|---|
| student_ability_score | education/internship/professional/certificate/innovation/learning/pressure/communication/problem_solving/teamwork 十个 `*_score` + total_score + score_type(1系统/2导师/3企业) + score_comment | 评分主表：训练结果写入处，score_type 建议用 **1-系统自动评分** |
| student_ability_score_history | 同上 + version + change_reason + profile_history_id | 评分历史留痕：每次训练写入一条新版本 |
| interview_record | question / answer_content / score / suggestion | 模拟面试存储（可扩展） |
| grow_task | target_ability / effect_score / adjustment_reason / adjustment_history / grow_recourse | 动态调整预留字段；训练成果可关联到成长任务完成情况 |
| student_profile | version | 画像版本号 |
