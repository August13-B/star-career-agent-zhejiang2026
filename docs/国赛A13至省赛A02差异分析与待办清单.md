## 一、现有代码全貌（已实现部分）

### 1.1 代码目录结构

```
星职/code/

├── 前端/Career Plannning  # Vue3 + Vite 前端（玻璃拟态 UI）
```

### 1.2 已实现功能清单

| 模块 | 位置 | 说明 |
|---|---|---|
| 用户体系 | 后端1 | 登录注册、JWT、RSA 加密传输、邀请码、多角色（学生/导师/企业/管理员） |

| 能力测评 | 后端1 | AI 能力测评（StudentAbility / AbilityScore / 评分历史） |

| 岗位知识库 | 后端2 | 岗位信息、岗位画像（硬/软/技能要求）、晋升图谱、转职图谱、市场信息 |
| 岗位 AI 分析 | 后端2 | 构建 Prompt → 调 AI 服务 → 自动解析入库（JobAIAnalysisService） |

| RAG 知识库 | AI 服务 | 161MB 向量库（knowledge_base.json）、岗位样本 Excel、PGVector + text-embedding-v4 |

### 1.3 技术栈现状

- 前端：Vue3 + Vite + Axios + ECharts（Glassmorphism 玻璃拟态）
- 后端：Spring Boot 3.x + MyBatis-Plus + MySQL + Redis（后端1）
- 岗位库：Spring Boot + MyBatis-Plus + MySQL（后端2）
- AI 服务：LangChain4j + 通义千问 qwen3-vl-plus + text-embedding-v4（DashScope）+ PGVector（PostgreSQL）+ Redis
- 调用链：前端 → 后端1 → AI 服务 → 大模型 API

## 二、方案文档承诺但【未实现 / 缺失】的部分

> 判定依据：《项目详细方案》《项目介绍PPT》中描述的架构与功能，对照代码逐项核查。
> 结论一句话：**"多智能体协同中枢"与"动态调整方案"整体缺失，SSE 流式只实现了最基础链路，B 端实时化与大数据基建未落地。**

### 2.1 🔴 核心缺失：MOE 多智能体协同中枢（后端）—— 完全未写

方案文档（3.3 章）承诺的**专家混合（MOE）多智能体协同网络**，后端零实现：

| 方案承诺 | 代码现状 |
|---|---|
| 意图路由智能体（Router Agent）：意图分类、模糊意图识别、置信度追问 | ❌ 无。AI 服务只有一个 `AIChatService` 接口 + RAG 检索 |
| 职业教练与人资智能体（Coach & HR Agent）：能力 Gap 诊断书、成功率预测 | ❌ 无。匹配只有简单加权计算，无 AI 诊断、无成功率预测 |
| 成长规划智能体（Planner Agent）：目标拆解、动态排期、计划重构 | ❌ 无。`grow_plan`/`grow_task` 只有表结构与实体，**无任何 Service 实现** |
| 情绪感知与韧性干预智能体（Emotion Agent）：情绪识别、分层干预、预警 | ❌ 无。后端/前端均无情绪相关代码 |
| 共享黑板（Blackboard）+ 冲突消解 + 五重交叉验证 | ❌ 无。无任何编排/黑板/消解代码 |
| 多智能体并行计算与结果融合 | ❌ 无 |

**关键证据**：前端 `MultiAgentView.vue`（"MOE 伴随式智能体协同大屏"）是**纯前端 Mock**——929 行全部为硬编码 HTML 输出 + `sleep()/setTimeout()` 模拟流程，**零 axios/fetch 调用**，不与任何后端交互。评审演示时是"演"出来的，不是真实推理。

### 2.2 🔴 核心缺失：动态调整方案（后端）—— 未写

方案文档（创新点 3、3.3.3）承诺的"目标导向动态成长反馈陪伴系统"：

| 方案承诺 | 代码现状 |
|---|---|
| 计划动态重构（进度变化 / 目标调整 / 情绪不佳时触发计划重排） | ❌ 无 |
| 任务依赖识别、先后顺序安排 | ❌ 无 |
| 动态排期（结合每日可投入时长、学习习惯、知识基础） | ❌ 无 |
| 情绪触发降级任务（中度负面情绪 → 切断高压计划流 → 降级任务） | ❌ 无 |
| 成长数据动态分析、动态调整计划 | ❌ 无 |

### 2.3 🟠 缺失：三层记忆驱动引擎

方案文档（4.2 章）承诺的瞬时 / 短期 / 长期三层记忆：

- ❌ `ChatController` 中 `chatMemory` / `chatMemoryProvider` **全部被注释掉**，会话记忆未接入
- ❌ Redis 滑动时间窗（15-30 天短期行为数据）无实现
- ❌ 短期 → 长期记忆转化（向量化沉淀）无实现
- ❌ 长期记忆唤醒（跨月/跨年召回用户画像）无实现
- ⚠️ 现状：对话历史仅按 `ai_message` 表存储，无分层记忆逻辑

### 2.4 🟠 缺失 / 不完整：SSE 流式输出（只完成最基础链路）

**已实现**：前端 fetch → 后端1 `/send-stream` → AI 服务 `/chat_with_flux`（SseEmitter）→ 前端 `ReadableStream` 逐块读取 → 假流式打字机（`charQueue` + `typeTimer`，Emoji 用 `Array.from` 防乱码）。

**方案承诺但未实现**：

| 方案承诺 | 代码现状 |
|---|---|
| SSE 心跳保活 + 断线自动重连 + 重传丢失数据块 | ❌ 无 |
| 残缺 JSON 符号 / 无效字符剥离 | ❌ 前端仅 `try/catch JSON.parse`，无健壮清洗 |
| 实时 Markdown 解析 | ❌ `formatText` 只是针对 `career_pathway` 等特定字段的正则替换，非通用 Markdown 渲染 |
| 流式过程中图表数据异步渲染（ECharts 边生成边渲染） | ❌ 无 |
| 流式渲染完成后自动持久化到账号（可随时查看/编辑/导出） | ❌ 流式通道不落库（`send-stream` 不保存 ai_message） |
| 流式过程用户可中断 / 失败重试 | ❌ 无 |

### 2.5 🟠 缺失：B 端全局态势感知大盘实时化

方案文档（3.5 章）承诺：

- ❌ WebSocket 实时推送（全后端无 `WebSocket`/`@ServerEndpoint`）
- ❌ RabbitMQ/Kafka 异步削峰队列（pom 无相关依赖）
- ❌ Flink 实时聚合计算
- ⚠️ 现状：`TutorDashboardView.vue`（360 行）为静态/轮询展示，无实时推送通道；后端无对应聚合服务

### 2.6 🟡 方案描述与实际实现不一致（需在省赛材料中修正或补齐）

| 方案宣称 | 实际 |
|---|---|
| Neo4j 图数据库 | 实为 MySQL 表（job_promotion_graph / job_transfer_graph） |
| Milvus 向量数据库 | 实为 PGVector（PostgreSQL）+ knowledge_base.json |
| 国密加密存储 | 仅有 RSA 传输加密，未见国密（SM4/SM2）存储实现 |
| 分布式集群（1主4从、Nacos、Docker） | 代码无对应部署配置（仅单机 Spring Boot） |
| 简历 OCR + 大模型信息抽取 | StudentImage 仅上传存储，抽取逻辑未见 |
| 成功率预测模型（PPT 称超 98%） | 无任何实现 |

## 三、国赛 A13 → 省赛 A02 赛题差异（要求发生变动的部分）

### 3.1 赛题对比

| 维度 | 国赛 A13（明杉科技） | 省赛 A02（蚂蚁百宝箱） |
|---|---|---|
| 题目 | 基于 AI 的大学生职业规划智能体 | 面向未来工作的 AI 职业导航或终身学习伙伴系统设计 |
| 目标用户 | 高校学生 | 所有年龄层与职业阶段用户（重点仍含学生） |
| 平台要求 | 无限制，自行选择 | **必须依托蚂蚁百宝箱企业版（b.tbox.cn）开发** |
| 大模型 | 至少一个 LLM | 百灵大模型、通义千问、DeepSeek |
| 协议 | 无要求 | **MCP 协议**（第三方服务对接） |
| 发布渠道 | 无要求 | Web（必选）+ 支付宝小程序 / 微信小程序（可选） |
| 核心闭环 | 画像 → 匹配 → 报告 | 感知 → 认知 → 决策 → 生成 → 执行 → 反馈（全技术闭环） |
| 路径规划 | 短期/中期成长计划 | **3-5 年职业发展路径**，可细化、可调整 |
| 场景模拟 | 无明确要求 | **至少 3 种职场场景模拟训练**（远程协作、AI 辅助办公、跨岗位沟通） |
| 陪伴机制 | 方案中有 Emotion Agent（未实现） | **人机信任与长期陪伴**：情感共鸣、目标监督激励（评分点） |
| 资源整合 | 岗位数据 | **教育、招聘、职业认证等第三方服务整合**（合规前提下 API 对接演示） |
| 伦理要求 | 一般提及 | AI 伦理设计（规避算法偏见、保护隐私、防过度依赖）为**重点加分维度** |
| 数据 | 企业提供 10000 条岗位数据 | 参赛团队自建高校生/职场新人模拟数据 |

### 3.2 需要改动 / 新增的工作清单（按优先级）

#### P0 — 必须（赛题硬性要求，缺失直接失分）

1. **蚂蚁百宝箱企业版平台适配**
   - 在 b.tbox.cn 上构建/编排智能体，配置知识库，完成调用与运行验证
   - 产出：平台配置说明 + 操作截图（提交材料 ⑥①）
   - 影响：现有自研 AI 服务（LangChain4j）需要评估是"迁移到百宝箱"还是"百宝箱作为前端渠道、自研服务作内核"（架构决策，见待确认问题）

2. **MCP 协议对接方案与实现**
   - 至少 1 个第三方服务通过 MCP 对接（如招聘/教育/认证数据源）
   - 产出：MCP 对接方案说明 + 实现（提交材料 ⑥③）

3. **多端发布验证**
   - Web 服务必选；支付宝小程序、微信小程序可选（加分）
   - 产出：多端发布验证截图（提交材料 ⑥④）

4. **3-5 年职业发展路径 + 动态调整（对应缺失部分）**
   - 路径需可细化、可调整——正好落在"动态调整方案未实现"这个缺口上，必须补写

5. **3 种职场场景模拟训练模块**
   - 远程协作、AI 辅助办公、跨岗位沟通；现有代码仅有模拟面试雏形（interview_record 表），需扩展

6. **动态职业画像 + 竞争力雷达图实时更新**
   - 现有画像为静态生成，需支持画像动态迭代（与动态调整联动）

#### P1 — 重要（评分重点 / 提交材料硬性项）

7. **多智能体协同中枢落地**（对应缺失部分）
   - 省赛"感知→认知→决策→生成→执行→反馈"闭环 + 个性化服务创新度加分，多智能体是核心载体
   - 建议至少实现：意图路由 + 职业教练/HR + 规划 + 情绪陪伴 4 个智能体

8. **AI 伦理设计专项**
   - 数据隐私保护（个人信息安全规范）、算法偏见规避、防过度依赖
   - 产出：技术架构与 AI 伦理设计说明文档（提交材料 (4)）+ 设计落地

9. **知识库构建方法与效果评估报告**
   - 现有知识库说明书可复用，需补充"效果评估"部分（召回率/准确率等）（提交材料 ⑥②）

10. **用户测试反馈与系统迭代记录**（提交材料 (5)）
    - 现有项目无此材料，需组织试用并整理记录

11. **大模型切换**
    - 按 A02 要求支持百灵大模型 / 通义千问 / DeepSeek；现有通义千问兼容，需补百灵适配 + 多模型可配置

#### P2 — 建议（完善度 / 演示效果）

12. **流式输出完整化**（对应缺失部分）：心跳、断线重连、JSON 清洗、Markdown 渲染、流式图表、落库持久化
13. **三层记忆落地**：会话记忆接入、Redis 短期记忆、长期画像沉淀与唤醒
14. **B 端大盘实时化**：WebSocket 推送 + 预警分级闭环（方案里是亮点，但代码是静态页）
15. **成功率预测 / 数字孪生**：PPT 宣称 98% 准确率但无实现，省赛不建议再写进材料，或补一个可解释的简化模型
16. **部署配置化**：隧道 URL、API Key、数据库连接等改为环境变量/配置文件

## 五、待确认问题（影响技术方案）

1. 蚂蚁百宝箱的定位：**A）仅作为演示/发布渠道**（业务内核仍用自研 LangChain4j 服务）；**B）智能体逻辑整体迁移到百宝箱平台**（自研服务仅做数据层）？——影响整个多智能体开发方式
2. 多智能体的实现载体：在 AI 服务（Java LangChain4j）里编排，还是百宝箱平台内编排？
3. 3 种职场场景模拟的实现深度：AI 对话模拟（轻）还是带任务提交/评分的完整沙盒（重）？
4. 省赛是否沿用"星职"项目名与品牌视觉？
