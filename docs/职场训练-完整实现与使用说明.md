# 职场训练：完整实现、使用说明与验收

更新：2026-09-24。基线 `origin/develop@2703ae0`，本地分支 `feat/workplace-training`。本轮没有提交、推送或创建 PR。本文描述当前可运行实现；早期总体设计中的候选接口、类名和里程碑不作为实际接口契约。

## 1. 从哪里开始

打开 `http://localhost:5173/training`，或点击左侧“职场训练”。先登录自己的账户。

大厅有三个已开放场景，可选择入门/标准难度，决定完整训练后是否更新已有能力画像。没有能力测评基线也可以练习，此时只保存反馈，不生成虚构的十维能力基线。

| 场景 | 操作流程 | 正式成果 |
| --- | --- | --- |
| Java 后端实习生模拟面试 | 6 个阶段：经历、技术取舍、幂等排查、需求协商、上线风险、复盘；第二阶段会结合第一阶段追问 | 问答记录、四维反馈与回答证据 |
| 跨岗位沟通：周五上线协调 | 与产品、开发、测试交互，共 5 阶段；对照固定资源与时间约束协商 | 协作确认单：范围、负责人、期限、验收、风险、待确认事项 |
| AI 辅助办公：活动复盘与核验 | 3 阶段：给 AI 布置任务、独立核验、修订交付；区分固定错误练习稿与本轮 AI 初稿 | 复盘摘要、待办清单、四项事实核验及修订依据 |

第一版每类提供一个固定模板，面试追问纳入六阶段，避免模型无限延长。多岗位题库、额外动态追问额度、语音视频、附件解析、参考答案生成及外部办公软件操作不包含在本版。

## 2. 一次完整训练怎样操作

1. 选择难度和画像更新选项，点击场景卡片“开始训练”。
2. 阅读任务材料及当前阶段。填写“我的回答”，点击“提交回答”。等待当前回复完成后进入下一阶段。
3. 沟通、办公训练还需填写下方作品区。草稿自动保存；“保存作品版本”将当前草稿保存为一个不可覆盖的历史版本。可展开历史版本查看过去内容。
4. 完成全部阶段，保存作品并点击“结束并评分”。提交时会自动保存作品的最新修改、校验必填项并冻结最后一个版本。
5. 查看得分、分维度反馈及引用证据。点击证据可定位到原始回答或最终作品。办公结果会额外显示固定材料的四项计算/决策核验。
6. 查看画像更新状态与十维前后对照；选择一条建议加入已有成长计划，再到“个人成长”查看待办。
7. 返回大厅，可按场景、状态筛选历史。再次训练会创建新记录；同模板、同难度且有效的完整结果可作前后比较。

### 离开、异常与重复操作

- 回答草稿和作品草稿分别保存并带版本号。离开页面会先保存，刷新后可恢复；生成任务在后端执行，切页不会主动取消它。
- 对话区域可独立滚动，整页也可滚动。390 像素窄屏下，训练页导航改为横向排列，内容区不会被固定侧栏挤压。
- 多标签页修改同一草稿发生冲突时保留当前输入并提示读取最新版。作品冲突可以保留旧输入于页面下方再读取。
- 可以跳过阶段或提前提交；这种情况只提供阶段性反馈，不更新能力画像。全部跳过导致缺乏有效证据时会显示“待复核”。
- 平台请求失败可重试，最多两次；用户答案不会因生成失败被删除。重试使用冻结的同一输入。
- 后端重启时：排队任务恢复执行，已中断的生成任务明确显示可重试。画像更新有持久化状态和后台恢复检查。
- “取消本次训练”是显式终止，取消后可回看但不能继续。迟到的平台回调不能恢复已取消的训练。
- 评分结构、模板版本、维度或证据不合法时，保留对话和作品，显示待复核；不显示未经验证的分数、不回写画像。

## 3. 评分与画像采用规则

模型只选择证据目录中的编号。后端从本人提交的原文还原引用，核对维度、模板/评分版本、分值范围与证据覆盖，重新计算本次训练加权分。沟通和办公的完整评分必须引用最终作品。AI 初稿不能充当用户提交成果。

办公固定材料的核验结果为：总报名 54 人、报名/意向总体转化率 18%、社群 25% 最高、增加投放尚未决定。结构化核验字段存在错误时，专业技能和问题解决两个维度最高为 59 分，页面明确标注 `office_facts_v1` 规则并重算总分。完整文稿的语义质量仍由模型结合证据评价。

自动更新画像必须同时满足：用户勾选允许更新、全部阶段实际作答、评分有效、开始时已存在完整关联的画像/能力/系统评分、采用时基线和画像版本未变化。无基线、取消、提前结束、跳过、无效评分、基线变化均不自动覆盖画像。

采用策略 `latest_observation_v1`：本次覆盖的四维使用这次训练的观察分；其他维度保留旧值。画像总分按硬能力四维平均值的 30% + 软能力六维平均值的 70% 计算，保留一位小数。原排名不沿用到新分数。

更新旧系统评分、新系统评分、画像版本、完整画像历史与评分历史在一个短事务内完成。既有画像中的加密字段仍以密文保存到历史快照；训练长文本使用 AES-GCM 存储。失败整体回滚，可单独重试画像更新；一次训练最多成功采用一次。

为防止冲突，本轮同时调整了旧能力评分写入：问卷与训练遵循用户锁，AI 分析在远程调用结束后用短事务替换评分；评分修改推进画像版本，画像编辑也在 SQL 中递增版本。查询个人系统评分优先返回最新有效系统记录。

成长任务从已验证的建议中选择，不能由客户端传入任意评价内容。一场训练最多关联一条任务；接口验证计划属于本人。完成成长任务不会直接增加能力分数。

## 4. 实际接口契约

统一前缀 `/api/training`，使用现有 `Authorization: Bearer <token>`。用户身份取 JWT；接口不接受客户端指定所有者。响应沿用 `Result`：业务成功码 `10001`；创建返回 HTTP 201，异步任务返回 202。所有雪花 ID 均以字符串提供给前端。

| 方法、路径（省略前缀） | 输入或用途 |
| --- | --- |
| `GET /templates` | 三类模板、轮次、材料、维度与作品字段 |
| `POST /sessions` | `templateId, clientRequestId, difficulty?, useForProfile?`；默认标准难度、API 默认不更新画像；UI 显式传选项 |
| `GET /sessions` | `offset=0, limit=20, templateId?, status?`；上限 50/页 |
| `GET /sessions/{id}` | 一致的会话快照：问答、草稿、任务、模板快照、作品版本、反馈、画像及成长关联 |
| `POST /sessions/{id}/turns` | `content, clientRequestId, expectedVersion, skip?`；回答最多 4000 字 |
| `PUT /sessions/{id}/draft` | `content, expectedVersion`；使用 `draftVersion` |
| `PUT /sessions/{id}/artifact-draft` | `content: {字段键:文本}, expectedVersion`；使用 `artifactDraftVersion` |
| `POST /sessions/{id}/artifacts` | `content, clientRequestId, expectedRevision`；追加作品版本，最多 50 个；字段及长度按模板校验 |
| `GET /sessions/{id}/artifacts/{revision}` | 查询本人指定作品版本 |
| `POST /sessions/{id}/finish` | `clientRequestId, expectedVersion`；冻结输入并异步评价 |
| `GET /sessions/{id}/evaluation` | 正式评价或待复核状态 |
| `GET /runs/{id}` | 当前异步执行状态 |
| `POST /runs/{id}/retry` | `expectedAttempt`；只重试本人最近失败任务 |
| `POST /sessions/{id}/cancel` | 显式取消，重复取消幂等 |
| `POST /sessions/{id}/profile/retry` | 单独重试待处理/失败的画像更新；不会重新调用模型 |
| `GET /growth/plans` | 本人的可用成长计划 |
| `POST /sessions/{id}/growth-task` | `planId, suggestionIndex`，索引从 0 开始 |

三种模板 ID：`interview_backend_intern.v1`、`communication_release.v1`、`office_review.v1`。创建后保存模板快照，后续修改模板不会悄悄改变旧会话规则。

会话状态：`active / scoring / completed / review_required / canceled`。执行状态：`queued / running / succeeded / failed / canceled`。评价状态：`valid / partial / review_required`。画像状态：`pending / applied / skipped / failed`，具体原因在 `message`。`completed` 不等于画像已更新。
