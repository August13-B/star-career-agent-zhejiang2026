## 本轮发现并修复的问题

1. **WebSocket 握手异常被包装为普通文字；没有收到 `RUN_FINISHED` 的断流也会正常结束。** 因此错误提示或半截回复可能被保存为完整回答。现统一发送错误帧，未收到终结事件即视为不完整，并在流结束时释放连接。
2. **问卷生成的能力记录缺少 `profile_id`。** 即使已经建档、完成问卷和 AI 分析，训练仍可能找不到关联的能力基线。问卷保存现在关联当前用户唯一有效画像；已有缺失关联的记录可在完善画像后重新提交问卷修复。没有批量修改原数据库。
3. **扩展测试引用已经软删除的成长任务。** 报告成功生成后会替换旧计划，测试现选取有效计划及任务。
4. **Python 验收脚本按默认编码读取 SSE。** SSE 应使用 UTF-8；已显式解码，避免中文字节被误识别为换行，导致错误帧 JSON 解析失败。

## 本机复现

以下在仓库根目录的 PowerShell 执行。首次需在测试 Python 环境安装 `requests pymysql cryptography aiohttp`；本轮已经安装。使用 Java 17、MySQL 8。

```powershell
$py = 'D:/my/.star-career-local/venv/Scripts/python.exe'
$env:JAVA_HOME = 'D:/my/.star-career-local/jdk/jdk-17.0.20.1+1'
$env:Path = "$env:JAVA_HOME/bin;$env:Path"
Push-Location 后端
./mvnw.cmd -q -DskipTests package
Pop-Location

& $py scripts/offline_acceptance.py start
$env:ACCEPTANCE_ENV_FILE = (Join-Path (Get-Location) 'logs/offline-acceptance/.env')
& $py scripts/project_acceptance.py --keep-fixtures
& $py scripts/project_extended_acceptance.py
& $py scripts/training_smoke.py
& $py scripts/offline_boundaries.py
& $py scripts/project_acceptance.py --cleanup
& $py scripts/offline_acceptance.py stop
Remove-Item Env:\ACCEPTANCE_ENV_FILE
```

启动器拒绝占用已有端口，每次创建新的 MySQL 数据目录；不会覆盖原库。其 `--java-home`、`--mysql-bin` 参数可适配其他电脑。故障注入改变本地模拟服务状态，必须在其他流程测试结束后单独运行，不要与训练或报告测试并发。
